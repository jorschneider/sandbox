# CRUX voice-bake tooling

Generates the pre-baked ElevenLabs voice clips in `boulder/audio/`.

The app plays a clip named by an FNV-1a hash of the **exact** phrase text, so the
phrase set here and the announcement logic in `boulder/index.html` must stay in
lockstep:

- `enumerate.js` mirrors the plan builders (`FOCI`, durations 15/30/45/60,
  grades V0–V12) and the announcement functions (`announceTextOf`,
  `longAnnounceTextOf`, `spokenLabel`). **If you change any spoken text or add a
  builder/drill in `index.html`, make the identical change here.**
- `bake.js` calls the ElevenLabs API (voice: Rachel, `eleven_multilingual_v2`)
  and writes `<hash>.mp3` files + `manifest.js`. Existing clips are skipped, so
  incremental re-bakes only pay for new phrases.
- `phrases.json` is the last enumerated phrase set (regenerated by enumerate.js;
  kept in git as the canonical record of what's baked).

## Re-bake after changing spoken text

```sh
cd tools/voice-bake
node enumerate.js phrases.json                       # regenerate the phrase set
XI=<elevenlabs-api-key> node bake.js full ../../boulder/audio

# loudness-match ONLY the new clips (existing ones are already normalized;
# re-encoding them again would degrade quality). Capture the file list before
# baking, then:
sox <new>.mp3 -C 128 tmp.mp3 norm -1 && mv tmp.mp3 <new>.mp3

# delete orphans: any boulder/audio/*.mp3 whose hash is not in manifest.js
```

Then verify every phrase maps to a clip (hash check), bump `CLIP_V` in
`index.html` **only if existing clips' audio content changed** (new URLs don't
need it), and deploy.

The API key is passed via the `XI` env var and must never be committed or
shipped — the deployed site is fully static and key-free.
